# Components

The CLI carries a trusted component catalog. Catalog entries define IDs,
sources, platforms, installation policy, and dependencies. Ownership receipts
record what was actually installed. A visible `a3s-*` executable on `PATH` can
be reported without being granted managed execution.

## Inspect state

```bash
a3s list
a3s list --installed
a3s list --available
a3s list --updates
a3s info use --sources --versions
a3s doctor
a3s doctor use
```

`list` and `doctor` are read-only by default. Under `--offline`, they use only
the local catalog, receipts, and cache.

## Install and upgrade

```bash
a3s install use
a3s install use/browser
a3s install use/ocr
a3s install box --dry-run
a3s upgrade
a3s upgrade use --yes
```

`install` without an ID only lists installable components. `upgrade` without an
ID only lists upgrades. `--dry-run` resolves a plan without mutation. An
automation host can review its digest and apply the same plan with
`--plan-digest SHA256`.

## Remove

```bash
a3s uninstall use --dry-run
a3s uninstall use --yes
a3s uninstall use --cascade --purge --yes
```

Removal is receipt-bounded. `--cascade` handles managed children first.
`--purge` also removes component-owned cache and runtime state. User-created
files are outside the receipt.

## Product proxies

```bash
a3s box ps
a3s compose up -d
a3s search doctor
a3s use browser open https://example.com
```

The CLI resolves a typed component ID, checks installation and platform state,
then launches the exact executable recorded by the receipt. The target product
owns its arguments and exit status.

Box and Use may perform a visible install on first real use. Read-only help,
version, list, and status paths do not download anything. Bench and Search
require explicit preparation.

## Use

Use is the capability entrypoint, not a second private protocol:

| Route | Implementation boundary |
| --- | --- |
| `a3s use browser ...` | Browser provider with standard MCP and Skill surfaces |
| `a3s use ocr ...` | Local OCR provider and pinned models |
| `a3s use office ...` | Office provider |
| `a3s use box ...` | The same managed Box component |
| `a3s use <extension> ...` | A verified registry extension |

When offline or under `A3S_NO_AUTO_INSTALL=1`, a missing capability returns an
explicit preparation command and does not mutate state.

## Registries

```bash
a3s registry list
a3s registry add https://packages.example.org/a3s/ \
  --trust-root ./root.json --yes
a3s registry refresh packages
```

An external registry is trusted through an explicit TUF root or pinned SHA-256.
The same package resolving from multiple trusted registries is rejected as
ambiguous.
