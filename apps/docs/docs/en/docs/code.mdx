# Code

`a3s code` starts the terminal workbench in the current workspace. The CLI owns
configuration, accounts, components, and process lifecycle. `a3s-code-core`
owns sessions, models, tools, permissions, Memory, delegation, and events.
`a3s-tui` owns terminal rendering and input.

## Start

```bash
a3s code
a3s -C /path/to/project code
a3s code exec "Review the public API and run its focused tests"
a3s code exec --mode plan --prompt-file task.md
```

`code exec` supports `default`, `plan`, and `auto` modes. `--model
PROVIDER/MODEL` overrides the model for one invocation.

## Sessions

```bash
a3s code resume
a3s code resume <session-id>
a3s code session list
```

A normal exit prints an exact resume command. Restored state includes the
transcript, model source, effort profile, execution mode, and TUI side state.

| Data | Default path |
| --- | --- |
| Core session snapshots | `.a3s/tui/sessions/v1/sessions` |
| TUI session state | `.a3s/tui/session-state/v1` |

`/fork` creates a session from the current transcript. `/fork worktree` also
creates an isolated Git worktree without changing the original repository
index.

## Execution modes

| Mode | Behavior |
| --- | --- |
| Default | Routine workspace changes can run; boundary crossings require confirmation. |
| Plan | Only read and analysis paths are open; approval starts a separate Default turn. |
| Auto | No human confirmation is opened; unproven host operations fail closed. |

Permission state is frozen when a run is admitted. Foreground, queued,
parallel, Skill, and background descendants keep that snapshot when the next
turn selects another mode.

| Command | Purpose |

| `/memory` / `/ctx` / `/kb` | Work with long-term Memory, context history, and the knowledge base. |

| `/fork` / `/rewind` / `/clear` | Branch, rewind, or clear a session. |
| `/auto` | Select risk-aware automatic execution. |
| `/update` | Save the session, update the CLI, and resume. |

## Tools and permissions

The model can call only tools registered in the session. Every invocation has
a name, structured arguments, event ID, timeout, and permission decision.

- File operations are scoped to the effective workspace.
- High-risk shell, protected metadata, mutating Git, and external side effects
  require explicit authority or fail.
- MCP and Use tools preserve their declared read, network, mutation, and
  destructive boundaries.
- Project grants are written to `.a3s/permissions.acl` as canonical operations
  and resources.
- Descendants inherit the parent run's permissions and confirmation boundary.

## Research

```bash
a3s code research --web "Compare Tokio and async-std"
a3s code research --local-only "Map this repository's release process"
```

Each run writes an event record, `report.md`, and editable `index.html` in its
own directory. Results distinguish completed synthesis, qualified evidence,
source-only output, and no evidence.
