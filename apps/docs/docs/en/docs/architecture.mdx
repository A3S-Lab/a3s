# CLI internals

```text
argv
  │
  ▼
clap::Cli / RootCommand
  │
  ▼
InvocationContext
  ├── workspace (-C)
  ├── ACL layers (--config)
  ├── output / interaction policy
  └── offline / first-use policy
  │
  ▼
typed command dispatch
  ├── Code / Web / Research ── in-process runtime
  ├── Config / Auth / Model ── root-owned services
  ├── Components ───────────── catalog + transaction engine
  └── Box / Search / Use ───── verified executable proxy
  │
  ▼
CommandOutcome / component exit status
```

## Entry

`src/main.rs` starts the async runtime, parses `Cli`, and hands completion to
one exit path. `src/cli/args.rs` defines global options and root commands with
Clap. Every command has typed arguments; unknown routes fail during parsing.

## Invocation context

`InvocationContext` fixes these values before dispatch:

- effective workspace and relative-path base
- explicit ACL file plus user and workspace layers
- human, JSON, or JSONL output
- network, prompt, progress, and first-use policy
- A3S data, state, cache, and component directories

Downstream commands receive this context instead of rediscovering configuration
from a mutable process directory.

## In-process paths

Code, Web, and Research share the CLI process:

| Route | Main modules |
| --- | --- |
| Code | `commands/code` → Code Core → TUI or headless event consumer |
| Web | `api/serve` → Code Web API → static Work assets |
| Research | `commands/code/research_runtime` → shared typed research engine |
| Config | `commands/config` → ACL resolver → validated persistence |
| Model | `commands/model` → unified model catalog → selected ACL layer |

These paths share configuration, accounts, models, and permission state without
a child-process text protocol.

## Component path

Independent products pass through four stages:

```text
typed component ID
  → trusted catalog
  → source / platform / receipt resolution
  → exact executable + forwarded argv
```

The transaction engine stages, verifies, and activates installs and upgrades.
Proxies execute receipt-recorded absolute paths. Discovered external programs
remain separate from managed components.

## Security boundaries

| Boundary | Constraint |
| --- | --- |
| Configuration | Parsed only with `a3s-acl`; displayed output is redacted. |
| Credentials | Third-party accounts retain their own stores; the CLI does not copy tokens. |
| Components | Provenance, digest, manifest, platform, and ownership are verified before activation. |
| Removal | Only receipt-proven files are removed. |
| Network | `--offline` disables both network access and first-use downloads. |
| Web | Loopback by default; remote exposure needs external authentication and TLS. |
| Tools | A Code run freezes permission state; descendants inherit that boundary. |
