# A3S Code capabilities

A3S Code makes important runtime decisions visible. A tool can be available to
the executor without being sent to the model on every turn; a risky call can be
paused before its side effect; remote work is registered only after login; and
historical context is recovered through an explicit, bounded command.

These are separate controls rather than one broad “agent mode.”

| Capability           | What it controls                                                        | What it does not do                                                                         |
| -------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Code Intelligence    | Read-only semantic symbols, navigation, and diagnostics for saved files | It does not edit files or execute a refactor. See [Code Intelligence](./code-intelligence). |
| Human in the loop    | Whether one exact boundary-crossing invocation may proceed              | It does not make a hidden tool safe or grant a broad shell wildcard.                        |
| Progressive tool API | Which registered schemas enter the model context for the current turn   | It is context disclosure, not authorization.                                                |
| `runtime`            | Login-gated remote execution of independent batch tasks                 | It is not available while signed out and still requires confirmation.                       |
| `/ctx`               | Explicit retrieval and optional preservation of prior-session context   | Historical text is reference material, not trusted instruction.                             |

## Human in the loop

When an invocation needs approval, A3S Code pauses the exact call before its
side effect and presents four decisions:

1. **Allow once**
2. **Allow exact capability for this session**
3. **Add exact capability rule to project**
4. **Deny and tell the agent why**

For example, the prompt can identify the operation as
`Bash(git push origin main)`. Choosing “Allow once” resumes that invocation
only. A project rule remains exact and the tool stays paused until the ACL write
succeeds. Denial can carry replacement guidance back into the conversation.

HITL is one stage in the invocation path:

```text
model tool call
  → mode and permission policy
  → tool-owned confirmation requirement
  → exact human decision
  → budget, timeout, cancellation, hooks, and sanitized result
```

Non-interactive Auto mode cannot ask a person, so an operation that would need
approval is denied instead of silently continuing.

## Progressive tool API disclosure

The executor retains the complete registered tool set. Before each model turn,
A3S Code selects the definitions that should enter that turn's context:

- Core repository tools remain available for normal coding work: file reads and
  writes, search, shell, Code Intelligence, delegation, and skill discovery.
- Web, fetch, Git, batch, program, and MCP definitions are added when recent
  textual intent asks for them.
- A standalone greeting receives no tool definitions.
- Selection considers recent non-tool text, so a short follow-up can preserve
  the intent of the active task.

For a request such as “commit the parser fix after tests,” the executor still
owns every tool, while the model receives core coding schemas plus Git. Web,
batch, program, and unrelated MCP schemas stay deferred.

This reduces repeated schema tokens. It does **not** bypass permission checks,
HITL, timeouts, cancellation, or tool-level confirmation.

## Login-gated `runtime` tool

The `runtime` tool appears only after `/login` establishes an active platform
session. Signing out removes it from the dynamic registry, so a signed-out model
does not see or call the tool.

The schema requires both parameters below:

| Parameter    | Type                        | Required | Contract                                                                                 |
| ------------ | --------------------------- | -------- | ---------------------------------------------------------------------------------------- |
| `tasks`      | array of strings or objects | yes      | One or more independent inputs to run in parallel.                                       |
| `worker`     | string                      | yes      | A tool-kind agent asset UUID or name. Names are resolved before submission.              |
| `timeout_ms` | integer                     | no       | Maximum full-batch wait. Default: 10 minutes. Completed results are retained on timeout. |

```json
{
  "tasks": [
    "Audit dependency risk",
    "Map the upgrade path",
    "Draft release notes"
  ],
  "worker": "release-research",
  "timeout_ms": 300000
}
```

The tool always requires confirmation because remote work can have cost or
external effects. After approval, it:

1. Resolves the worker name when necessary.
2. Submits every input as one remote batch with an idempotency key.
3. Streams queued, running, and done counts without blocking the batch.
4. Polls with bounded backoff and tolerates transient failures.
5. Collects finished outputs concurrently.

A retry reattaches to the same batch instead of spending twice. If the budget
expires, the result explicitly reports `partial: true`, returns the completed
subset, and includes the batch identifier needed for inspection.

## `/ctx` cross-session context

`/ctx` is an explicit recall surface for prior coding-agent sessions:

| Command         | Result                                                                                   |
| --------------- | ---------------------------------------------------------------------------------------- |
| `/ctx <query>`  | Search prior sessions and display up to eight addressable hits.                          |
| `/ctx <n>`      | Retrieve a bounded transcript window for hit `n` and stage it for the next message only. |
| `/ctx save <n>` | Promote the selected hit into durable memory with event and session provenance.          |

Example:

```text
/ctx why did auth refresh fail?
/ctx 1
```

The second command does not permanently grow the conversation. It attaches the
selected transcript window to the next message once, then clears the staged
context. `/ctx save 1` is the explicit path for preserving a useful decision.

### Historical text is untrusted

Past tool output can contain obsolete code or prompt-injection-like text. A3S
Code therefore:

- strips control and ANSI sequences;
- caps the attached transcript at 6000 bytes;
- quote-prefixes every line so embedded fences cannot escape the historical
  block;
- labels the block as untrusted reference material;
- preserves `ctx_event_id` and `ctx_session_id` when the user saves a hit.

The agent should verify a recalled decision against the current workspace
before acting on it.

## How the capabilities compose

A single coding turn can use all of these boundaries without conflating them:

```text
/ctx recalls the prior decision
  → Code Intelligence locates the current semantic target
  → progressive disclosure keeps the turn's schemas focused
  → HITL pauses an exact external side effect
  → runtime fans out approved independent work after login
```

Each layer remains observable, bounded, and independently testable.
