# 组件管理

CLI 内置可信组件目录。目录记录组件 ID、来源、平台、安装策略和依赖关系；安装 receipt
记录实际归属。`PATH` 中偶然出现的 `a3s-*` 程序可以被列出，但不会自动获得执行权限。

## 查看状态

```bash
a3s list
a3s list --installed
a3s list --available
a3s list --updates
a3s info use --sources --versions
a3s doctor
a3s doctor use
```

`list` 与 `doctor` 默认不修改状态。`--offline` 下只使用本机目录、receipt 和缓存。

## 安装与升级

```bash
a3s install use
a3s install use/browser
a3s install use/ocr
a3s install box --dry-run
a3s upgrade
a3s upgrade use --yes
```

没有组件 ID 的 `install` 只列出可安装项；没有组件 ID 的 `upgrade` 只列出升级。
`--dry-run` 生成操作计划，不写入文件。自动化环境可以先审查计划 digest，再用
`--plan-digest SHA256` 应用同一计划。

## 删除

```bash
a3s uninstall use --dry-run
a3s uninstall use --yes
a3s uninstall use --cascade --purge --yes
```

删除范围受 receipt 限制。`--cascade` 先处理受管子组件；`--purge` 额外删除该组件归属的
缓存与运行状态。用户自己创建的文件不属于 receipt。

## 产品代理

```bash
a3s box ps
a3s compose up -d
a3s search doctor
a3s use browser open https://example.com
```

CLI 解析 typed component ID，检查安装和平台条件，再直接启动 receipt 记录的可执行文件。
参数与退出码由目标产品负责。

Box 和 Use 可以在首次真实使用时进行可见安装。只读 help、version、list 和 status
不会触发下载。Bench 与 Search 需要显式准备。

## Use

Use 是能力入口，不是第二套私有协议：

| 路径 | 实现边界 |
| --- | --- |
| `a3s use browser ...` | Browser provider 与标准 MCP/Skill surface |
| `a3s use ocr ...` | 本地 OCR provider 与固定模型 |
| `a3s use office ...` | Office provider |
| `a3s use box ...` | 同一受管 Box 组件 |
| `a3s use <extension> ...` | 已验证 registry extension |

离线或 `A3S_NO_AUTO_INSTALL=1` 时，缺失能力直接返回准备命令，不会在后台修改状态。

## Registry

```bash
a3s registry list
a3s registry add https://packages.example.org/a3s/ \
  --trust-root ./root.json --yes
a3s registry refresh packages
```

外部 registry 使用显式 TUF root 或固定 SHA-256 建立信任。相同包在多个可信 registry
中同时出现会被视为歧义，不会按顺序猜测。
