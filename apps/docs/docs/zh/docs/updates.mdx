# 更新

CLI 自身与独立组件使用两条更新路径。

```bash
a3s self update --check
a3s self update --dry-run
a3s self update --yes

a3s upgrade
a3s upgrade use --yes
```

## CLI 自更新

`a3s self update`：

1. 读取当前编译版本与安装来源。
2. 解析适合当前平台的稳定 release。
3. 校验 release digest、归档结构和 staged binary 版本。
4. 先暂存，再原子激活。
5. 确认新二进制能报告目标版本。

Homebrew 安装由 Homebrew 更新；standalone 安装使用匹配平台的 release archive。
macOS 与 glibc Linux 支持进程内自更新。Windows 通过重新运行 PowerShell 安装器升级。

## Code 内更新

`a3s code update` 与 TUI `/update` 进入同一 CLI 自更新流程。TUI 会先保存当前 session，
退出后更新，再执行：

```bash
a3s code resume <session-id>
```

如果自动重启失败，终端仍会打印这条恢复命令。

## 组件升级

`a3s upgrade` 不带 ID 时只检查；显式传入组件或 `--all` 才会修改：

```bash
a3s upgrade --dry-run use
a3s upgrade use --plan-digest <sha256>
a3s upgrade --all --yes
```

组件先下载到 staging，完成来源、checksum、manifest、平台和协议检查后才切换 active
version。提交失败时保留上一份健康版本和 receipt。

## 离线

```bash
a3s --offline upgrade
a3s --offline install use --version <version>
```

离线模式只读取缓存材料，不访问 release 或 registry。缓存中缺少精确产物时会失败，不会降级到
未校验来源。
