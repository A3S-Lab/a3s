A3S Cloud is no longer the NestJS sample used by the previous version of this article. The current control plane is written in Rust, stores business state in PostgreSQL, and uses A3S Flow to continue long-running work.

DDD is useful here for three practical questions: who may change a piece of state, which invariants must hold for that change, and where execution resumes after a failure.

## Modules follow business ownership

The control plane includes modules such as `identity`, `projects`, `workloads`, `fleet`, `edge`, `operations`, `assets`, `agents`, `secrets`, and `sources`. Each follows the same four-layer shape:

```text
modules/<module>/
├── domain/
├── application/
├── infrastructure/
└── presentation/
```

- `domain` contains entities, value objects, rules, and repository interfaces without HTTP or PostgreSQL dependencies.
- `application` contains commands, queries, and their handlers.
- `infrastructure` implements PostgreSQL, object storage, Git, and external-service adapters.
- `presentation` maps REST, SSE, or Management MCP calls to commands and queries.

The directory structure is secondary. The real rule is that `fleet` owns nodes and command journals, `edge` owns desired Gateway state, and `workloads` owns deployment intent. One module does not update another module's tables directly to save a call.

## What happens during a deployment command

A create or update request broadly follows this path:

1. The presentation layer resolves tenant context, request ID, and idempotency key.
2. A command handler loads domain objects and checks organization, project, environment, and version constraints.
3. A repository transaction writes desired state, an idempotency record, and an outbox event.
4. `operations` creates a durable identity for the long-running action.
5. A3S Flow continues scheduling, node-command delivery, health-evidence waits, and retries after the HTTP request returns.
6. Query projections expose the same business result to REST, CLI, Web, and Management MCP.

The HTTP request does not stay open until deployment finishes. Its job is to commit intent and an Operation identity reliably.

## Idempotency is more than returning 200 twice

Cloud stores the idempotency scope, key, and a digest of the canonical request.

- The same key and same request can replay the original result.
- The same key with different input is a conflict.
- Node commands also have stable identities, so an Agent restart does not invent another deployment.

An in-memory cache in a controller cannot provide this behavior across process restarts or replicas.

## The outbox and Flow solve different problems

The outbox keeps a committed business transaction and its integration event together. The relay publishes only messages already stored in PostgreSQL.

A3S Flow manages stateful long-running work: steps, waits, retries, hooks, cancellation, and recovery. It is not a domain repository and does not decide whether a Workload revision is valid.

```text
Domain decides what may happen
Repository stores business facts atomically
Outbox carries committed facts across module boundaries
Flow continues long work across failures
```

## Cloud does not event-source every entity

Authoritative business state remains in PostgreSQL tables behind domain repositories. A3S Flow uses an append-only run history, but that does not require every aggregate to be rebuilt from events.

Version fields, transactions, and audit records are enough for ordinary project names and environment settings. Persistent step history earns its cost for deployments, builds, node commands, and agent executions that span processes and failures.

## Current delivery boundary

The `F0` foundation is verified. Box-only migration, external source delivery, control surfaces, agent publishing and execution, and production-scale work continue under explicit roadmap gates. Evidence from the retired Docker path does not automatically certify the new Box-only path.

That is the practical value of DDD in this repository: ownership and completion criteria live in modules and gates, so the presence of code is not presented as a finished product.
