A3S Gateway 1.0.12 is the current stable release. It is an ACL-configured Rust data plane: accept traffic, choose an allowed healthy backend, and switch complete runtime snapshots without invalidating requests already in flight.

It is not the Cloud control plane. It does not create model replicas, store tenants, schedule workloads, or replace a coding agent.

## Why AI requests need different lifecycle rules

The difference is not the URL. It is the request lifetime.

- SSE and WebSocket sessions may run for minutes and cannot be buffered as one response.
- Response-header timeout, stream-idle timeout, and total duration are different limits.
- Once an upstream has started responding, Gateway cannot silently retry against another model.
- Model authorization depends on endpoint, model grant, snapshot generation, and concurrency policy—not only a path.
- Downstream disconnect must release upstream work, backend accounting, and usage state together.

Gateway now gives SSE independent response-header, idle-stream, and total-operation limits and uses drop guards to release request and connection accounting.

## One request reads one runtime snapshot

```text
ACL or Cloud snapshot
        │
        ▼
validate ──> compile ──> atomic swap ──> active snapshot
                                          │
client ─> route ─> middleware ─> service ─> healthy backend
```

A new configuration is validated in full. A failed reload leaves the previous working snapshot active. The request path does not synchronously call Cloud, PostgreSQL, or a scheduler.

That is the main Gateway invariant: the control plane may be temporarily unavailable while traffic authorized by a still-valid local snapshot continues.

## Protocol and operations surface

The stable data plane supports HTTP/1.1, HTTP/2, SSE, WebSocket, gRPC, TCP, UDP, and TLS. Routing covers host, path, method, header, and SNI, with health checks, load balancing, limits, authentication, retries, circuit state, mirroring, and static revision weights.

The embedded Web console is served by the Management listener and needs no Node.js process or external asset server:

```bash
a3s-gateway --config gateway.acl web
```

It reads real configuration, topology, request logs, performance, and Gateway-observed traces. With no traffic, it stays empty rather than seeding demo telemetry.

## Standalone and Cloud-managed modes

| Mode | Desired-state owner | Gateway responsibility |
| --- | --- | --- |
| `standalone` | Local ACL | Validate and execute routing, protocol, health, and middleware policy |
| `cloud-managed` | A3S Cloud | Validate and apply complete versioned, digest-bound snapshots |

A managed snapshot binds Gateway ID, increasing revision, expected previous revision, SHA-256, issue time, and expiry. Invalid, expired, conflicting, or stale successors are rejected while the active snapshot remains in service.

## The OpenAI request path

Gateway has a closed profile for `/v1/models`, chat completions, legacy completions, and embeddings. It validates JSON and model fields, enforces authorization and grants, rewrites the upstream model, and permits fallback only before the first response byte.

This is not a promise to implement every OpenAI extension. Requests outside the closed profile retain ordinary proxy behavior.

## What is not a shipped production capability

| Capability | Current state |
| --- | --- |
| HTTP/SSE/WebSocket/gRPC/TCP/UDP/TLS | Available |
| Atomic ACL reload and managed snapshots | Available |
| Embedded operations console | Implemented on `main`, listed under Unreleased |
| Local coding-agent profiles and Skill launch | Implemented on `main`, listed under Unreleased |
| Standalone autoscaling | Experimental; complete real Box/Kubernetes certification remains open |
| Automatic gradual rollout and rollback | Controller types exist, but no runtime loop drives them; unavailable |
| Native MCP or agent-protocol data plane | Planned |

The older article described automatic rollback and production autoscaling as current features. That did not match the repository roadmap.

## Install and validate

macOS or Linux:

```bash
curl --proto '=https' --tlsv1.2 -LsSf \
  https://a3s-lab.github.io/Gateway/install.sh | sh
```

Windows PowerShell:

```powershell
irm https://a3s-lab.github.io/Gateway/install.ps1 | iex
```

The installers verify the release checksum and binary-reported version. Validate ACL before binding listeners:

```bash
a3s-gateway validate --config gateway.acl
a3s-gateway config --config gateway.acl summary
a3s-gateway --config gateway.acl
```
