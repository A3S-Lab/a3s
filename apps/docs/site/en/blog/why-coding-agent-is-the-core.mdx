A3S Code 6.8.0 is the current stable release. It is neither a chat loop nor a wrapper around one model vendor's CLI. It separates the coding-agent runtime into replaceable contracts for models, workspaces, tools, policy, events, and persistence.

## The shortest path to a running session

The terminal product ships through the A3S CLI:

```bash
brew install A3S-Lab/tap/a3s
cd /path/to/project
a3s code
```

Applications can embed the Rust Core or use the Node.js, Python, and Go SDKs. All four surfaces share Session, event, and tool semantics instead of maintaining separate agent implementations.

## `Agent` and `AgentSession`

`Agent` resolves ACL configuration and shared capabilities. `AgentSession` binds them to one workspace and conversation.

```rust
use a3s_code_core::{Agent, AgentEvent};

let agent = Agent::new("agent.acl").await?;
let session = agent.session_builder(".").build().await?;
let (mut events, lifecycle) = session.stream("Find the auth entry points.", None).await?;

while let Some(event) = events.recv().await {
    if let AgentEvent::TextDelta { text } = event {
        print!("{text}");
    }
}

let _ = lifecycle.await;
```

A UI does not need access to Core internals. Text, tools, approvals, plans, tasks, and terminal states are delivered through the event stream.

## Tools are not an unconditional registry

Code registers tools according to workspace capability and policy.

- A local workspace can expose files, shell, Git, code navigation, and downloads.
- An object-only backend does not advertise local `bash` or `git` to the model.
- Calls pass through argument validation, permission checks, human confirmation, budgets, sandboxing, and cancellation.
- `batch` parallelizes only calls declared safe and read-only. Writes and unknown tools are serialized.

Release 6.8.0 consolidated repository discovery under `search`, with regex content search, path globbing, and bounded BM25. Delegation moved to the unified `task` contract for one task or a 1–32 item fan-out.

## Resume from evidence

`SessionSnapshotV1` can atomically store conversation state, runs, artifacts, traces, verification reports, and child-task records. `EventEnvelopeV1` is the lossless event protocol shared by SDK streams and persisted runs.

`resume` therefore does more than resend a transcript. A host can load the authoritative run, inspect its checkpoint, and continue the same Session.

Release 6.8.0 also added the bounded `a3s.code.agent.v1` headless protocol for exact release, session, and run admission, cancellation, checkpoint recovery, and event paging. It reuses Code's run store instead of creating a second Harness journal.

## Programmable surfaces

Core currently provides three orchestration entry points:

| Surface | Best fit |
| --- | --- |
| `task` | Model-directed single or concurrent delegation |
| `program` | Bounded QuickJS code calling allowed tools |
| `dynamic_workflow` | A3S Flow-backed replay, retries, and recovery |

`program` cannot recursively call itself or `dynamic_workflow`. Dynamic workflows are also registered explicitly by the host; a type existing in Core does not mean every embedding enables it automatically.

## 6.8.0 versus `main`

The stable release includes unified `task`, BM25 search, detached-run admission across SDKs, the headless agent protocol, and the Go SDK.

Current `main` also contains a filesystem Skill Catalog. It lists metadata by repository and user scope, reads `SKILL.md` only on demand, and supports path-specific enablement and change notifications. That work is still under `Unreleased`; stable-package users should not assume it has shipped.

## Code's place in A3S

Code owns governed agent execution. A3S Flow owns durable workflows, A3S Box owns local isolation, A3S Gateway owns traffic, and A3S Cloud owns organization state and desired state. Moving those responsibilities back into Code would create competing sources of truth for permissions and recovery.
