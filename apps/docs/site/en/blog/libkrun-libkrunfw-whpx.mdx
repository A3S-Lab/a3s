A3S Box 3.2 can boot Linux OCI workloads directly on x86-64 Windows through WHPX. WSL is not part of this runtime path.

Four components are involved:

```text
a3s-box.exe
  └─ krun.dll            libkrun VMM and WHPX backend
       ├─ libkrunfw.dll  Linux guest kernel
       └─ a3s-box-guest-init  PID 1 inside the guest
```

`libkrun` owns virtual-machine lifecycle and devices. `libkrunfw` carries the Linux kernel. Box owns OCI images, root filesystems, persistent state, forwarding, and the user-visible lifecycle.

## Why the Windows package contains a Linux executable

`a3s-box-guest-init` runs inside the MicroVM, not on the Windows host. It is cross-linked with Zig as a static Linux executable and becomes guest PID 1. It mounts filesystems, starts the workload, relays output, and handles shutdown.

A runnable package needs at least:

```text
a3s-box.exe
a3s-box-shim.exe
a3s-box-guest-init
krun.dll
libkrunfw.dll
```

Both DLLs must remain next to the Windows executables. A missing runtime component is a hard error.

## OCI symbolic links cannot be approximated

Linux images commonly use symbolic links for `/bin`, dynamic loaders, and library paths. The Windows path stores the root filesystem on NTFS and serves it to the guest through virtio-fs.

The host therefore needs Windows Developer Mode or `SeCreateSymbolicLinkPrivilege` for the service identity. Replacing a symbolic link with a copied file or junction would change OCI layer, whiteout, and guest path semantics, so Box fails instead.

## What has been validated

The project ran real WHPX validation on July 20–22, 2026, using Windows 11 Pro build 26200 and an AMD Ryzen 7 9800X3D. The documented scope includes:

- foreground and detached Alpine 3.20 runs;
- stdout, stderr, logs, exit codes, and cleanup;
- published TCP ports;
- read-only bind mounts and named volumes;
- successful and failing initialization scripts;
- `diff`, `export`, stopped-state `commit`, and filesystem snapshots;
- a 12-case soak matrix that finished without residual shims, forwarders, or runtime objects.

The validated `libkrunfw.dll` booted Linux 6.12.91. This evidence covers the named host and workload matrix, not every CPU, Windows build, or Box feature.

## Current limitations

| Capability | Windows/WHPX status |
| --- | --- |
| vCPUs | Exactly one |
| Foreground and detached `run` | Validated |
| Published TCP ports | Validated |
| Post-boot `exec` and interactive PTY | Unsupported |
| Bridge networking and Compose service networking | Unsupported |
| Container health checks | Rejected before start |
| Snapshot-fork | Unsupported |
| TEE | Unsupported |
| CRI | Unsupported |

Requests such as `--cpus 2` or a health-check configuration fail before image pull. Box does not silently continue through a reduced-capability backend.

## Host checks

Enable Windows Hypervisor Platform from an elevated PowerShell prompt and restart if requested:

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName HypervisorPlatform
```

After installation, run:

```powershell
a3s-box info
```

It should report both `Virtualization: WHPX` and `OCI symlink support: available`. If either check fails, fix the host before debugging guest logs.
