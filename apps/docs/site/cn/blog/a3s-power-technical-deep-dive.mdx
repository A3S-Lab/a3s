A3S Power 当前稳定版是 0.7.0。旧文章标题里的“10 美元硬件、256MB 跑 10B 模型”不是当前项目可以稳定复现的发布承诺，已经删除。

Power 现在有两个入口：

| 入口 | 用途 | 网络行为 |
| --- | --- | --- |
| `embedded-inference` | OCR、视觉或语言模型仓库复用设备、权重、准入和收据基础设施 | 不开启 listener |
| 默认 server | 提供 OpenAI-compatible chat、completion、embedding 与模型生命周期 | 显式启动服务 |

两者共享同一套资源与完整性契约，但模型图、Tokenizer、前后处理和质量验收仍由模型仓库负责。

## 嵌入式运行时负责什么

Power 的嵌入式路径提供：

- CPU、CUDA、Metal 的类型化设备选择；
- 有界请求、Session、内存和设备队列；
- SafeTensors 身份、校验、replica 和按范围读取；
- mmap、缓存与预取的可测量策略；
- 取消、资源释放和规范化执行收据；
- 不携带输入内容的硬件证据结构。

它不内置 PP-OCR、文档解析或任何产品模型。比如 A3S OCR 可以使用 Power 的权重与设备层，但 OCR 图结构和输出语义仍属于 OCR 项目。

最小依赖：

```toml
[dependencies]
a3s-power = { version = "0.7.0", default-features = false, features = ["embedded-inference"] }
```

```rust
use a3s_power::inference::{DevicePreference, EmbeddedRuntime, InferenceLimits};

let runtime = EmbeddedRuntime::new(
    DevicePreference::Auto,
    InferenceLimits::default(),
)?;
```

## 服务端路径

默认 server 提供 `/v1/chat/completions`、`/v1/completions`、`/v1/models` 和 `/v1/embeddings`。当前后端包括 mistralrs，另有可选 llama.cpp、picolm 和 OpenAI-compatible proxy 路径。

picolm 走纯 Rust GGUF layer-streaming，目标是把峰值权重驻留控制在单层规模。项目当前文档记录的是“7B+ 模型在 512MB TEE EPC”这一能力边界，而不是旧文中的 10B/256MB。具体模型、量化方式、上下文长度和硬件仍需单独跑基准。

## TEE 能证明什么

TEE 模式把硬件报告、nonce、启动度量、模型摘要、运行策略和请求收据绑定起来。客户端验证器决定接受哪些度量和证据。

```text
model artifact ──hash/signature──┐
runtime policy ──────────────────┼─> canonical claims
request nonce ───────────────────┘         │
                                           ▼
                                  SEV-SNP / TDX report
                                           │
                                           ▼
                                      client verifier
```

RA-TLS 可以把证明放进证书扩展；推理响应可以携带请求级收据摘要。严格验证会拒绝模拟报告，并要求调用方固定预期 measurement。

需要注意：代码支持某种 ioctl 或证据格式，不等于某台生产机器已经通过安全认证。固件、证书链、启动镜像、GPU 证明、部署方式和侧信道策略都属于最终验收范围。

## 模型隐私措施

当前实现包含模型 SHA-256 与 Ed25519 校验、AES-256-GCM 加密模型加载、敏感字符串 zeroize、日志字段清理和可选 token 指标降精度。

这些措施各自解决不同问题：

- 加密文件保护静态权重；
- TEE 保护特定威胁模型下的运行内存；
- 证明让客户端检查运行环境；
- 日志清理减少应用层泄露。

不能把其中一项写成对所有宿主、管理员和硬件攻击的笼统保证。

## 0.7.0 与 main

0.7.0 增加了验证过的 SafeTensors 范围索引、可选 buffered/direct reads 和独立存储基准工具。当前 `main` 继续加入多存储根容量聚合、有界推理队列、模型 Session Pool、microbatch 计划和硬件证据 bundle；这些仍在 `Unreleased`。

## 使用前的检查

1. 先决定需要嵌入式库还是网络服务。
2. 把模型语义和正确性测试留在模型仓库。
3. 对具体硬件记录模型、量化、上下文、吞吐和峰值内存。
4. TEE 部署使用严格 verifier，不把模拟模式带进生产。
5. 把证据 bundle 固定到签名发布或其他信任根；SHA-256 本身不是签名。
