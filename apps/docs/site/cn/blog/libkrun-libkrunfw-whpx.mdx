A3S Box 3.2 可以在 x86_64 Windows 上通过 WHPX 直接启动 Linux OCI 工作负载。WSL 不在这条运行路径里。

这条链路由四个部件组成：

```text
a3s-box.exe
  └─ krun.dll          libkrun VMM + WHPX 后端
       ├─ libkrunfw.dll  Linux guest kernel
       └─ a3s-box-guest-init  guest 内的 PID 1
```

`libkrun` 负责虚拟机生命周期和设备模型；`libkrunfw` 携带启动所需的 Linux 内核；Box 负责 OCI 镜像、根文件系统、状态、网络转发和用户可见的生命周期命令。

## 为什么 Windows 包里有一个 Linux 可执行文件

`a3s-box-guest-init` 在 MicroVM 内运行，不是在 Windows 宿主上运行。它由 Zig 交叉链接成静态 Linux 程序，作为 guest 的 PID 1，负责挂载、启动工作负载、转发输出和处理关闭请求。

一个可运行的 Windows 包至少包含：

```text
a3s-box.exe
a3s-box-shim.exe
a3s-box-guest-init
krun.dll
libkrunfw.dll
```

两个 DLL 必须与 Windows 可执行文件放在同一目录。缺少其中任何一个，运行时都会直接失败。

## OCI 符号链接不能偷懒

Linux 镜像通常把 `/bin`、动态加载器或库路径做成符号链接。Windows 路径使用 NTFS 保存根文件系统，并通过 virtio-fs 提供给 guest。

因此宿主需要启用 Developer Mode，或给服务身份授予 `SeCreateSymbolicLinkPrivilege`。如果 Box 把符号链接偷偷改成复制文件或目录联接，OCI layer、whiteout 和 guest 内路径解析都会改变，所以当前实现选择失败退出。

## 已验证的范围

项目在 2026 年 7 月 20–22 日使用 Windows 11 Pro build 26200 和 AMD Ryzen 7 9800X3D 做过真实 WHPX 验证。当前文档记录的范围包括：

- Alpine 3.20 的前台与后台运行；
- stdout、stderr、日志、退出码与清理；
- TCP 端口发布；
- 只读 bind mount 与命名卷；
- 初始化脚本成功和失败路径；
- `diff`、`export`、停止状态的 `commit` 与文件系统快照；
- 12 项 WHPX soak 矩阵结束后无残留 shim、转发进程或运行时对象。

验证使用的 `libkrunfw.dll` 启动了 Linux 6.12.91。这个结果只证明被测 Windows 主机和工作负载矩阵，不代表其他 CPU、Windows 版本或功能自动通过。

## 当前限制

| 能力 | Windows/WHPX 状态 |
| --- | --- |
| vCPU | 仅 1 个 |
| 前台/后台 `run` | 已验证 |
| TCP 端口发布 | 已验证 |
| `exec` 与交互式 PTY | 不支持 |
| Bridge 网络与 Compose 服务网络 | 不支持 |
| 容器健康检查 | 不支持，启动前拒绝 |
| Snapshot-fork | 不支持 |
| TEE | 不支持 |
| CRI | 不支持 |

请求 `--cpus 2`、健康检查或其他未支持能力时，Box 会在拉取镜像前返回明确错误，不会换一条低配路径继续跑。

## 启动前检查

管理员 PowerShell 中启用 Windows Hypervisor Platform，按系统提示重启：

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName HypervisorPlatform
```

安装后先运行：

```powershell
a3s-box info
```

输出应同时包含 `Virtualization: WHPX` 和 `OCI symlink support: available`。这两个条件不满足时，先修宿主环境，不要从 guest 日志里猜。
